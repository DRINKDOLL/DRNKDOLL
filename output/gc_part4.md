## 第八章 页面清单

**小程序端（学员）**：广场首页、分类列表页、搜索结果页、作品详情页、投稿表单页（分步）、我的作品页、作品数据页、团队主页与团队管理页、消息中心、作者个人页。

**公众号 H5（访客）**：广场首页（免登录）、作品详情页（带水印）、访客留言、Demo 跳转中间页、分享落地页。

**PC 后台（老师 / 助教 / 管理员）**：登录页、工作台（待审积压 + 今日上墙）、审核队列（初审 / 终审）、作品管理、分类与标签、推荐位配置、团队管理、访客留言治理、举报处置、外链巡检、课例推送、数据看板、操作日志、接口监控。

## 第九章 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-G01 | 性能 | 列表与搜索接口 P95 ≤ 800ms，首屏 ≤ 1.5s；作品详情首屏 ≤ 2.5s，视频与截图懒加载不阻塞首屏；含 9 图 + 1 视频的投稿提交 ≤ 20s；首版并发按一个教学班 120 人同时浏览设计 |
| NFR-G02 | 媒体存储 | 对象存储 + CDN + 签名 URL，禁止裸桶与直链；图片统一转 WebP；视频 H.264 转码后播放；水印在边缘生成 |
| NFR-G03 | 安全 | 服务端强制鉴权，前端隐藏不作为权限依据；受限作品、草稿、待审内容不得被未授权角色通过任何接口获取（含 IF-08）；外链白名单 + 新窗口 + noopener；富文本必须防 XSS；防爬采用列表限速、详情关键字段服务端渲染、批量抓取触发人机校验 |
| NFR-G04 | 可用性 | 核心链路（浏览、投稿、审核、Demo 跳转）日可用率 ≥ 99%；审核后台 ≥ 99.5%，因为审核断流等于上墙断流；巡检任务失败不影响主站 |
| NFR-G05 | 内容安全与合规 | 全部 UGC 过 IF-06；实名讨论区先审后发，访客留言机审即发 + 10% 抽审；警务与涉密内容一律不得公开展示；审核日志不可删除，留存 ≥ 6 个月。访客无 uid，无法禁言，只能设备封禁，治理强度天然低于实名区，此为本平台已知风险，见 R-G04 |
| NFR-G06 | 数据留存 | 作品与其版本、媒体永久保留，毕业后转校友态只读；操作日志 ≥ 6 个月；访问统计明细保留 90 天、聚合数据永久；删除作品的墓碑记录永久保留 |
| NFR-G07 | 备份与恢复 | 业务库每日全量 + 增量，保留 ≥ 30 天；对象存储开启版本控制；上线前完成一次含媒体文件的实际恢复演练 |
| NFR-G08 | 兼容 | 微信客户端近两个大版本；访客 H5 兼容 iOS Safari、Android Chrome、微信内置浏览器；PC 后台支持 Chrome / Edge 最新两个版本 |
| NFR-G09 | 可维护与交接 | 接口文档、部署文档、数据库变更脚本、版本迭代说明四项齐备；巡检、审核、统计三类定时任务的失败告警必须可在后台看到 |

## 第十章 验收标准

| 编号 | 验收项 | 标准 |
| --- | --- | --- |
| AC-G01 | 投稿闭环 | 材料齐全的投稿 6 步内提交成功；缺任一必填项被双层校验拦截并定位到字段 |
| AC-G02 | 审核时效 | 任一投稿 24 小时内出结论；超时出现在告警名单；两级审核不可跳级 |
| AC-G03 | 上墙与徽章 | 工坊项目上墙后展示「已验收」徽章与评分；非工坊项目无任何形似评分的数字 |
| AC-G04 | 可见范围 | 受限作品不出现在列表、搜索、推荐位与 IF-08 返回中；访客访问返回统一提示页 |
| AC-G05 | 媒体与安全 | 媒体直链返回 403；9 图 + 1 视频投稿 ≤ 20s；跨域与 XSS 用例全部拦截 |
| AC-G06 | 互动分流 | 访客留言不出现在实名讨论区；同一 uid 重复点赞只计一次；举报 1 分钟内入队 |
| AC-G07 | 状态机 | 七态流转可走通且每步留痕；作者下架后记录与积分不丢；恢复需重新过审 |
| AC-G08 | 版本切换 | 新版审核期间线上维持旧版；通过后原子切换，不出现双版本或空白 |
| AC-G09 | 外链巡检 | 人为下线 Demo，2 天内出现失效标识并通知作者；恢复链接后自动复原 |
| AC-G10 | 积分分账 | teamId 传 5 人（1 队长 4 成员），队长 +20、成员各 +5，合计 40；重复 eventId 不重复加分 |
| AC-G11 | 看板准确 | 看板指标与明细列表抽样核对一致；待审积压量实时刷新 |
| AC-G12 | 可交接 | 非开发者按文档 1 天内完成部署；接口文档与 Mock 齐备 |

## 第十一章 依赖与风险

| 编号 | 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- | --- |
| R-G01 | IF-07 未按时提供 | 徽章与评分无法上线 | 先用 EV-04 缓存 + 人工补录过渡，徽章标「待核验」 |
| R-G02 | 全公开带来合规压力 | 涉密内容外泄 | 涉密红线清单前置（Q-11）+ 先审后发 + 涉警类强制受限 + 上线前校方书面确认 |
| R-G03 | 外链失效 | 体验形同虚设 | 巡检 + 通知 + 30 天归档；以视频与截图作兜底体验 |
| R-G04 | 访客留言不可追溯 | 违规内容无法追责 | 设备封禁 + 10% 抽审 + 每 500 条人工全量复核一次；责任主体需校方明确（Q-12） |
| R-G05 | 审核人力不足 | 上墙断流、作者流失 | 助教排班 + 批量通过（限 20 条）+ 驳回模板；SLA 告警前置到 12 小时 |
| R-G06 | 冷启动无作品 | 广场空墙 | 上线前预置首批 15 件（补齐历史工坊验收项目投稿）+ 教师推荐位 |
| R-G07 | 学员团队流动大 | 交接断层 | 沿用总纲 NFR-10，AC-G12 为硬验收项 |
| R-G08 | 团队主数据双轨 | 与工坊队伍不一致 | 绑定 teamId 者以工坊为准；纯广场团队仅承载非工坊作品；每学期做一次一致性核对 |

## 附录 C 假设清单

以下为本平台在编写时采用的假设，任一不成立需回溯修改对应章节：

1. 技术形态沿用总纲 3.8：小程序 + 公众号 H5 + PC 后台，三端共用同一套后端接口与数据模型。
2. 审核人力由助教与老师承担，不设专职审核岗；24 小时 SLA 按工作日计算。
3. 广场不做评分、不做投票、不做评奖，所有分数均来自工坊验收结论。
4. 访客体系依赖微信公众号；未关注者仅能查看分享链接的单页。
5. 作品永久保留，校友态只读且可维护旧作的维护字段。
6. 首版为 P0 最小闭环；榜单、推荐位、课例回流、作者数据概览按 P1 / P2 排期。
7. 总纲 2.4 的「每学期 ≥ 10 个项目推送至成果广场」作为 M4 量化目标继承，验收时以该数为基线。
