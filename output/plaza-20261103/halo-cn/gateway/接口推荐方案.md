# 广场对接警院WeChat网关 · 接口推荐方案

> 背景：广场已按《统一身份与网关接入说明文档》完成 L2 签名、身份头校验、错误码透传等核心接入组件（代码已就位于 `gateway/` 包并逐条验证通过）。现针对「对接警院WeChat 平台 + 预留实训工坊」业务场景，梳理需要设计的接口清单，并按图例格式给出每个接口的完整契约与落地顺序。

## 一、新增接口总览（均走统一网关、服务态调用）

| 接口 | 职责 | 关键输入 |
|---|---|---|
| `GET /api/v1/internal/works` | 供论坛按用户分页查询广场公开作品列表 | uid、page、size |
| `GET /api/v1/internal/works/{workId}` | 按作品主键查详情摘要 | workId |
| `GET /api/v1/internal/works/by-project/{projectId}` | 供工坊/论坛查是否已投稿 | projectId |
| `GET /api/v1/internal/works/by-team/{teamId}` | 供论坛查团队作品 | teamId |
| `GET /api/v1/internal/teams/{uid}` | 用户团队归属查询（IF-09 可选） | uid |
| `GET /api/v1/internal/lab/acceptance/{projectId}` | 广场消费工坊验收结论（IF-07） | projectId |
| `GET /api/v1/internal/lab/badges/{workId}` | 按作品查认证徽章状态 | workId |
| `GET /api/v1/user/works/{workId}` | 用户态：网关注入身份后查本人作品（越权拦截） | workId + 身份头 |

> **注**：前 7 个为**服务态**接口（消费方 AppKey + L2 签名）；最后一个为**用户态**接口，
> 鉴权模型不同——由**网关**在转发时注入 `X-User-Id` 等身份头与 `X-Internal-Sign`，
> 广场侧校验内部签名（失败 403/40303）、令牌有效期（过期 401/40103）与水平越权（403/70002）。

## 二、接口详细契约

> 统一约定：所有服务态接口均走 **L2 签名**（`X-App-Key` + HMAC-SHA256，见 `gateway/sign.py`），**只读**，默认拒绝，限流 100 QPS，不返回草稿/待审/已下架/受限作品。错误响应统一 `{"code","message","data","requestId"}`。

### 1. GET /api/v1/internal/works — 作品列表（IF-08）

- **请求方式**：`GET`
- **鉴权方式**：L2 服务签名（AppKey `svc-forum` / `svc-study` / `svc-lab`，按路由白名单）
- **入参**（Query）：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| page | int | 否 | ≥ 1，默认 1 |
| size | int | 否 | 1 ≤ size ≤ 100，默认 20 |
| uid | str | 否 | 用户主键 |

- **出参**：`{ page, size, total, items: WorkSummary[] }`
- **错误码**：`40105` 签名无效、`40106` 时间戳越界、`40107` nonce 重复、`40303` 直连未鉴权、`70007` 白名单拒绝、`42901` 触发限流
- **调用频率建议**：单 AppKey ≤ 200 QPS、接口 ≤ 100 QPS、单令牌 ≤ 20 QPS

### 2. GET /api/v1/internal/works/{workId} — 作品详情（IF-08）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名
- **入参**（Path）：`workId`（str，非空）
- **出参**：`WorkSummary` + `excerpt`（摘要）+ `memberUids`（团队成员）
- **错误码**：同上，另 `70001` 作品不存在、`70002` 作品不可见
- **调用频率建议**：≤ 100 QPS

### 3. GET /api/v1/internal/works/by-project/{projectId} — 按项目查投稿（IF-08）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名
- **入参**（Path）：`projectId`（str，非空）
- **出参**：`{ submitted: bool, workId: str|null }`
- **错误码**：`70001` 项目无关联、`70007` 白名单拒绝
- **调用频率建议**：≤ 100 QPS

### 4. GET /api/v1/internal/works/by-team/{teamId} — 按团队查作品（IF-08）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名
- **入参**（Path）：`teamId`（str，非空）
- **出参**：`{ page, size, total, items: WorkSummary[] }`
- **错误码**：`70001` 团队无作品、`42901` 限流
- **调用频率建议**：≤ 100 QPS

### 5. GET /api/v1/internal/teams/{uid} — 用户团队归属（IF-09 可选）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名
- **入参**（Path）：`uid`（str，非空）
- **出参**：`{ teamId: str|null, role: str|null }`
- **错误码**：`70001` 用户无归属
- **调用频率建议**：≤ 100 QPS

### 6. GET /api/v1/internal/lab/acceptance/{projectId} — 消费工坊验收结论（IF-07）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名（AppKey `svc-plaza` 作为调用方）
- **入参**（Path）：`projectId`（str，非空）
- **出参**：`{ projectId, teamId, accepted, score, comment, verifiedAt }`
- **错误码**：`70004` 工坊服务不可用（触发徽章降级）、`70005` 项目未验收
- **调用频率建议**：≤ 50 QPS（受工坊限流约束，需与工坊对齐）

### 7. GET /api/v1/internal/lab/badges/{workId} — 认证徽章查询（预留）

- **请求方式**：`GET`；**鉴权方式**：L2 服务签名
- **入参**（Path）：`workId`（str，非空）
- **出参**：`{ workId, certified, verifiedAt, pendingCheck }`
- **错误码**：`70001` 作品不存在
- **调用频率建议**：≤ 100 QPS

## 三、接口间调用依赖关系

```
IF-08 作品列表/详情/按项目/按团队  ── 依赖 ──▶  IF-07 验收结论（派生 certified 徽章字段）
        ▲
        │（certified 字段取值）
        └── 读取 ──▶  GET /lab/badges/{workId}（徽章状态）
```

- **IF-07 → IF-08**：广场消费 IF-07 验收结论后，将 `accepted` 派生为作品摘要的 `certified` 字段，供 IF-08 各查询接口返回。
- **IF-07 → 徽章接口**：徽章接口的 `certified/pendingCheck` 直接取自 IF-07 的消费缓存；IF-07 不可用时 `pendingCheck=true` 并沿用上次结果（降级）。
- **IF-09（团队归属）→ IF-08（按团队查）**：先查团队归属拿到 `teamId`，再按 `teamId` 查作品，存在前置依赖。

### 8. GET /api/v1/user/works/{workId} — 用户态作品查询（网关转发）

- **请求方式**：`GET`；**鉴权方式**：网关注入身份头（非 AppKey 签名）
- **入参**：Path `workId`；Header `X-User-Id` / `X-User-Role` / `X-Token-Exp` / `X-Internal-Sign` 等
- **出参**：`WorkSummary`（仅本人或管理员可见）
- **错误码**：`40303` 绕过网关直连（缺/错 `X-Internal-Sign`）、`40103` 令牌过期、`70002` 水平越权、`70005` 作品不存在
- **调用频率建议**：≤ 100 QPS

## 四、推荐实现优先级

| 优先级 | 接口 | 理由 |
|---|---|---|
| P0（先行） | `GET /works`、`GET /works/{workId}` | IF-08 核心只读，是论坛/自学/工坊消费的基础，打通 L2 签名主链路 |
| P1 | `GET /works/by-project/{projectId}`、`GET /works/by-team/{teamId}` | 补全按项目/团队维度查询，满足工坊「查是否已投稿」与论坛「查团队作品」 |
| P2 | `GET /lab/acceptance/{projectId}`（IF-07）、`GET /lab/badges/{workId}` | 依赖工坊侧就绪，作为第二批联调 |
| P3（可选） | `GET /teams/{uid}`（IF-09） | 团队归属属可选能力，最后落地 |

## 五、配套改动

- `gateway/contracts.py` 增加 `WorkDetail.member_uids`、`BadgeState` 等字段契约（已就位）。
- `gateway/server.py` 路由白名单按「精确路径 + 目录前缀」收紧，`svc-forum` 仅放行 IF-08，`svc-lab` 额外放行 `/lab/` 预留接口。
- 作品摘要 `certified` 字段由工坊验收结论派生，禁止手动标注；IF-07 不可用时标记「待核验」并沿用上次结果。

## 六、两个关键设计取舍

1. **列表接口 `certified` 字段走派生而非实时查询**：实时逐条回调工坊会放大 QPS 与耦合，改为消费 IF-07 后异步落地徽章缓存，IF-08 只读缓存，保证只读接口稳定且 P95 附加延迟可控。
2. **查询接口一律 GET + 只读、写操作另行走审核链路**：与网关「服务态默认拒绝、只读」口径一致，避免服务态接口越权改数据；作品发布/审核仍走 Halo 控制台受控写路径。
