### GF-09 多版本与更新日志（P1）

- **触发**：作者在作品详情页点「发布新版本」，或在投稿时选择向已有作品追加。
- **规则**：v1 为上墙版本；新版本内容可与旧版完全不同；新版本必须重新过审，审核期间线上仍展示旧版，审过后原子切换。
- **保留**：全部历史版本可查（作者与管理员），公开页只显示当前版本与更新日志（版本号、日期、更新说明 ≥ 10 字）。
- **版本号**：主版本号自动递增（v1 → v2），作者不可自定义。
- **验收要点**：切版过程中任一时刻详情页只有一个可用版本，不出现空白页或双版本并存。

### GF-10 个人作品集与创作团队主页（P1）

- **个人页**：作者头像（取自一号通）、姓名与班级、作品数、总浏览量、获赞数、已上墙作品列表（含参与团队的作品，并标注本人在该作品中的角色）。对访客仅展示姓名、班级与作品，不展示任何统计明细。
- **团队主页**：团队名、团队简介（≤ 200 字）、成立时间、成员列表（角色与加入时间）、团队作品集、团队总览数据。
- **团队创建**：学生自建、邀请制。创建者自动为负责人，可邀请成员（站内通知 + 对方确认），可移出成员（需填理由，被移出者保留历史作品的署名）。
- **与工坊队伍的关系**：团队可绑定一个工坊 teamId（主），绑定后成员与验收信息以工坊为准、广场不可修改；未绑定的为纯广场团队，成员完全由负责人维护，且只能承载非工坊项目作品。
- **归属约束**：一人可属多个团队；同一作品只能归属一个团队。
- **验收要点**：绑定 teamId 的团队，其成员列表与 IF-07 返回不一致时以 IF-07 为准并提示负责人确认；团队作品数须等于该团队名下已上墙作品数。

### GF-11 榜单、推荐位与运营位（P1）

- **推荐位**：首页首屏 3 个编辑推荐位，管理员可配置作品、生效时间与排序，每学期至少轮换一次。
- **热度榜**：周榜、学期榜、分类榜；只统计实名行为（浏览 UV、点赞、留言、体验点击），访客行为不计入。
- **明确不做**：学生投票评选、星级打分榜、「最佳作品」评审。理由见 1.3 边界判定第 2 条。
- **两类推荐标识**：管理员可标「编辑推荐」（运营语义），老师可标「教学推荐」（教学语义），视觉不同、语义不同，均不产生分数。
- **验收要点**：榜单每小时刷新一次；刷新失败保留上一版并告警，不得出现空榜。

### GF-12 课例回流入口（P1）

- **触发**：老师在作品详情页或后台勾选「转为教学课例」，填写建议用途（前置必修 / 选修拓展 / 案例讲解）与目标课程（可为空）。
- **产出**：生成一条 EV-06 事件推送给自学平台，自学平台接单后建课；广场侧作品标记「已转课例」，课例上线后回填跳转链接。
- **拒绝**：自学平台可拒绝（不适用 / 与现有课例重复），拒绝原因回传广场并通知勾选老师。
- **权限**：仅老师与管理员可勾选；作者可对被转为课例提出异议，异议由勾选老师处理。
- **验收要点**：勾选后自学平台可见 ≤ 1 分钟；拒绝链路可走通并留痕。

### GF-13 举报与申诉接入（P0，复用底座）

- 复用论坛 FR-09 的举报队列、处置手段与申诉通道，广场只提供入口与对象类型，不另建治理体系。
- **对象类型**：作品（work）、校内评论（workComment）、访客留言（guestComment）、团队主页（team）。
- **理由分类**（针对作品场景）：疑似涉密或未脱敏、侵权或抄袭、技术描述失真、Demo 含恶意内容、广告导流、其他。
- **处置手段**沿用折叠、下架、删除、禁言、冻结；针对作品额外支持「退回待审」。
- **申诉**：作者对下架不服可申诉一次，由管理员终审；申诉期间作品维持下架状态。
- **验收要点**：从举报到处置全流程可走完且留痕；访客留言被处置后，同一设备 24 小时内不得再留言。

### GF-14 广场 PC 管理后台（P0）

- **模块清单**：审核队列（初审 / 终审两个视图，领取锁定、批量通过、驳回模板）、作品管理（检索、强制下架、恢复、置顶）、推荐位配置、分类与标签维护、团队管理（解散、强制移出成员）、访客留言治理、举报与处置记录、外链巡检结果、课例推送记录、数据看板、操作日志审计、接口与事件监控。
- **权限分流**：助教只见初审队列与讨论区治理；老师见终审、评语、课例勾选；管理员全量。
- **批量操作**：单次批量通过上限 20 条，必须逐条确认徽章与可见范围，不提供「全选一键通过」。
- **验收要点**：任一审核动作均可回溯到操作人、时间、理由；后台不存在「删除审核日志」入口。

### GF-15 消息通知（P0，复用 IF-05）

- **通知类型**：审核结果（通过 / 驳回 / 退回）、作品被留言、作品被举报、Demo 失效告警、团队邀请、被选为课例、作品被下架。
- **渠道**：站内消息 + 微信订阅消息（需授权，沿用论坛 FR-12 的授权引导策略）。
- **频控**：同一作品同一类型的通知 24 小时内合并为一条；访客留言不触发订阅消息，仅站内红点。
- **验收要点**：驳回通知必须含原因分类与修改指引；订阅消息授权引导不得阻塞投稿主流程。

### GF-16 数据看板（P0，最小集）

首版只做两组核心数字加互动关键数，避免看板空转：

1. **审核效率**：待审积压量、平均审核时长、超 24 小时未处理数、驳回率与驳回原因分布。
2. **内容供给**：上墙总数、本月新增、作品类型分布、验收项目占比、团队作品占比。
3. **互动与反馈**：留言量、作者回复率、收藏数、举报量与处置率。
4. **曝光与转化**（P1）：详情页 PV / UV、Demo 点击率、外链失效数、访客占比。

口径：按自然日统计，T+1 出数；实时数只提供待审积压量。**验收要点**：看板数字与后台明细列表条数抽样核对一致，误差为 0。

### GF-17 外链健康巡检（P0）

- **频率**：每日 03:00 全量巡检一次；新上墙作品在上墙后 1 小时首检。
- **判定**：HTTP 状态非 2xx / 3xx、响应超时 10 秒、页面标题或正文命中「404 / not found / 已停止访问」关键词、证书错误，均判失效；连续 2 次巡检失败才标记失效，避免误判。
- **处置链**：标记「体验已失效」（详情页按钮置灰并显示说明）→ 站内通知作者 → 7 天未修再次提醒 → 30 天未修自动转「已归档」并从公开列表移除。
- **记录**：每次巡检写一条 experienceCheck 记录（workId、时间、状态码、耗时、判定结果）。
- **验收要点**：人为下线一个 Demo，2 天内作品页出现失效标识且作者收到通知。

### GF-18 版权声明与水印（P1）

- **版权协议**：投稿时二选一——「保留所有权利」（默认）或「CC BY-NC-SA 4.0」；选择后作品页展示对应协议标识与可复制的声明文本。
- **水印**：公开页封面与截图右下角标注「作者姓名 · 班级」；访客页额外叠加斜向淡纹「学校简称 · 成果广场」；水印在 CDN 边缘生成，不修改原图。
- **转载**：作品页提供「引用请标注作者与来源」的一键复制文本；不提供任何形式的打包下载。
- **验收要点**：切换协议后作品页标识与声明文本同步变化；原图直链始终不可访问。

### GF-19 作者数据概览（P2）

- 作者在个人中心可查看本人作品：浏览量趋势、Demo 点击数、留言数、收藏数、访客来源占比（校内 / 校外）。
- 不做竞品对比、排名与粉丝画像。
- **验收要点**：作者只能看到本人作品数据，越权查询他人作品统计返回 403。

## 第五章 关键业务流程

### BP-G1 自主投稿到上墙

学员在小程序点投稿 → 选类型、填基础信息组 → 传封面与截图（自动压缩与水印）→ 选可见范围与版权协议 → 提交 → 系统校验必填项并做敏感词预检 → 状态置「待审」并通知助教 → 助教初审（素材、涉密、侵权）→ 通过则转终审，驳回则填原因退回 → 老师终审 → 通过则状态置「已上墙」，同时发出 EV-05（积分记账、档案写入）、进入最新列表 → 通知作者与团队成员 → 作品可被搜索与推荐。

### BP-G2 工坊验收项目上墙（认证通道）

工坊终期验收通过 → 发出 EV-04 → 广场收到 EV-04 后为该项目预生成「待投稿」占位（不自动上墙）→ 队长或成员进入投稿，按 projectId 带出项目名、成员、技术栈、验收评分与导师评语 → 作者补封面、截图、体验链接、可见范围 → 提交待审 → 与自主投稿共用同一队列，但审核视图标注「已验收」→ 通过上墙，展示徽章与评分 → 积分按队长 20、成员平分 20 记账 → 档案写入。

### BP-G3 外链失效处置

每日巡检 → 连续 2 次失败标记失效 → 详情页按钮置灰 → 站内与订阅消息通知作者 → 作者更新链接后自动恢复（无需重新过审，仅记录变更）→ 30 天未修转「已归档」，从公开列表移除，作者与管理员仍可见 → 归档后作者修复仍可申请恢复。

### BP-G4 访客留言治理

访客在详情页留言 → 图形验证 → 敏感词与图片机审 → 通过即在访客留言区展示并进入 10% 抽审池 → 命中则直接拦截、不展示、入人工队列 → 作者可回复一次 → 任何人可举报 → 举报进入论坛治理队列 → 处置（折叠 / 删除 / 设备封禁 24 小时）→ 访客无账号，结果不回传，仅站内告知作者。

### BP-G5 下架与恢复

**作者主动下架**：二次确认（提示「作品将退出公开展示，记录保留，可申请恢复」）→ 状态置「已下架」，从列表与搜索移除，详情页仅作者与管理员可访问 → 申请恢复需重新过审 → 过审回到「已上墙」。**管理员强制下架**：填理由 → 状态置「已下架」→ 通知作者 → 作者可申诉一次 → 管理员终审。

### BP-G6 版本更新与重审

作者点「发布新版本」→ 编辑内容（可换封面、换 Demo、改说明）→ 提交 → 对外状态仍为「已上墙」，内部标记「新版待审」，线上维持旧版 → 审核通过 → 原子切换为新版、版本号 +1、更新日志追加一条 → 通知收藏过该作品的用户（受频控合并）。

### BP-G7 优秀作品回流课例

老师浏览作品 → 勾选「转为教学课例」→ 填建议用途与目标课程 → 生成 EV-06 → 自学平台接单并建课 → 建课完成回填课例链接 → 作品页显示「本作品已作为 XX 课程课例」→ 作者收到通知并可提出异议。

### 7.3 广场对外的接口（本次新增）

- **IF-08 作品查询**：按 uid 查作品列表（分页）、按 workId 查详情摘要、按 teamId 查团队作品、按 projectId 查是否已投稿。消费方为论坛（个人主页）、自学平台（课例引用）、工坊（项目页展示成果）。只读、带签名、限流 100 QPS，且不得返回草稿、待审、已下架与受限作品。
- **IF-09 团队与作品关联查询**（可选）：供论坛个人主页展示团队归属时使用，若论坛不展示团队则可不实现。

| --- | --- | --- | --- |

### 7.5 广场消费的事件

EV-04 项目验收通过：用于预生成待投稿占位与徽章校验缓存。消费失败进重试队列（指数退避，最多 5 次）并告警，不允许静默丢弃。

### 7.6 接口硬约束

- 全部接口提供文档与 Mock；变更必须版本化，不允许直接改已有字段语义。
- 事件消费按 eventId 幂等。
- **降级策略**：IF-07 不可用时，已有作品的徽章沿用上次校验结果并标注「待核验」，不阻断展示；新投稿暂不允许获得徽章，但不阻断投稿。
