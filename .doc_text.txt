执行摘要
本文档是警院 WeChat 全生态五平台中第四平台（成果展示广场）的开发依据，承接总纲第三章的全局规则与 M4 里程碑。广场是五平台闭环的第五环与唯一出口，只做四件事：展示、体验、反馈、传承。
本次需求澄清确定三条关键决策：其一，广场对公网完全开放，作品提交即公开、不设前置人工审核，以"涉密承诺书 + 机审标记 + 2 小时响应下架"作为补偿性控制，构成对总纲 NFR-02 的正式偏离；其二，广场严格守住"展示"定位，不做关注关系、不做推荐流、不做热度榜，评分与榜单只作作品质量参考；其三，优秀作品的课例回流采用"作者授权 + 老师审批"双条件，不由系统自动流转。
首版 P0 范围为：投稿上墙、展示墙、作品详情、体验中转页、评论点赞评分、巡查与下架、广场管理后台。榜单、搜索、版本迭代、课例回流列 P1。
需决策层在开发启动前拍板两件事：一是总纲负责人对第九章偏离条款的书面确认（附录 D 记录确认状态）；二是非工坊来源作品的积分分值（第十三章 Q-11）。

[000005] 2.1 平台定位
成果展示广场是五平台闭环的第五环与唯一出口。它不生产内容，只做三件事：把工坊产出的项目变成可被全校看见的作品，把看见变成可沉淀的反馈，把反馈变成下一届可以接手的资产。
用一句话概括职责：展成果、做曝光、收反馈、做传承。
总纲 3.5 给广场的边界是"不做开发过程管理，不重开评审"。本文档在此之上补一条同等级约束：广场不做社区。具体体现为三条禁止项——不设关注与粉丝关系、不做算法推荐信息流、不做以浏览量与评论数为基础的热度排行。榜单只以"作品质量"为口径，不以"社区活跃"为口径。理由见 2.5。

[000005] 2.3 建设目标
业务目标
让每一个通过验收的项目都有对外可见的落点，解决"做完没人知道"的问题。首版目标为工坊来源项目上墙率不低于 80%。
让低年级学员在动手之前就能看到可运行的真实作品，把"看作品"作为选方向、找队友、定选题的入口。
让作品产生可被使用的反馈，反馈以"建议、缺陷、想参与"三类归集到作者，而不是散落在聊天记录里。
让优秀作品沉淀为教学资产，通过课例回流（EV-06）进入自学平台，形成闭环自转。
技术目标
复用底座身份与权限（IF-01、IF-02），广场不自建账号体系，不维护第二套角色定义。
完全公开的浏览侧与校内受限的互动侧解耦：未登录可读，写操作一律鉴权。
与工坊、自学平台只通过接口与事件通信，不跨库读写。

[000005] 2.5 与总纲边界的确认（重要）
本项目在需求澄清阶段曾考虑把广场做成"含关注、热度榜、创作者主页的轻社区"。经决策，不采用该方向，理由有三：
总纲 3.5 已明确广场"不做内容社区"，若广场引入关注流与热度榜，将与其职责边界冲突，也会与论坛的社交职能重叠。
完全公开场景下，热度类指标极易被刷，且无法区分校内与校外流量，作为校内评价依据不可靠。
警务类作品一旦以热度为曝光依据，会把"传播性"置于"合规性"之上，与本项目的内容安全底线相悖。
因此本文档确定：评分与榜单只作为作品质量参考，不作为社区热度指标；排序口径见 SP-FR-09。

[000005] 3.3 登录与身份
广场不提供独立注册与登录页，一律通过 IF-01 校验论坛颁发的统一 token，从中取 uid、角色与权限快照。
浏览侧不强制登录：展示墙、详情页、评论列表、评分分布对访客全部可见，便于对外传播。
写操作（评论、投稿、评分、点赞、举报）在服务端做登录与角色校验；访客执行写操作时返回登录引导，不跳转空白页。
账号被冻结时，广场侧同步失权：历史作品保留展示但作者无法登录管理，处置权归管理员。
[000005] 3.4 访客态与校友态的特殊规则
访客评分只写入热度计数，不进入质量参考榜，也不参与"作品评分"的公开展示口径（详情页展示的评分仅统计校内实名评分）。
访客不可见的内容：作者真实姓名与学号、团队成员的班级信息、工坊内部评审意见原文。这三类在任何情况下不对外暴露。
校友态账号保留浏览与点赞能力，保留本人作品的管理权（可申请下架），但不能投稿新作品，与总纲"校友态只读"保持一致。

[000005] 4.2 SP-FR-01 作品投稿与上墙（P0）
作品进入广场有两条来源通道，共用同一张作品表，但校验规则不同。
通道一：工坊推送
工坊项目验收通过并产生 EV-04 后，工坊侧提供"推送到成果广场"动作，广场接收后生成作品草稿，自动带入项目名称、团队成员、技术栈、验收评分与评审结论摘要。
草稿状态的作品仅作者与管理员可见，作者补全封面图、作品简介、体验地址、源码是否公开等信息后提交，即上墙。
上墙前广场调用 IF-07 复核项目状态，状态非"验收通过"则拒绝上墙并回写失败原因。
同一项目重复推送时按 projectId 幂等，不产生重复作品。
通道二：自主投稿
任何人可投稿，不设学历、年级、成绩门槛。来源类型可选：工坊项目、自学课程作业、竞赛作品、个人作品。
自主投稿必须填写：作品名称、来源类型、作品简介、封面图、技术栈、参与成员（可单人）、体验地址（选填）、源码地址（选填且默认不公开）。
自主投稿不校验验收状态，但详情页必须显著标注来源类型；非工坊来源的作品统一显示"未经项目验收"提示，避免与工坊来源作品混淆。
共同规则
投稿前必须勾选《不含涉密与敏感信息承诺书》，勾选记录与提交时间入库留痕，见第九章。
成员与贡献权重由投稿人填写，权重合计须为 100%，用于积分分账，规则见 7.5。
作品提交后立即上墙，不进入人工审核队列，与第九章偏离条款配套的事后巡查机制承接质量与合规责任。
作者可随时编辑作品信息、提交新版本、申请下架。申请下架后即刻从公开展示中移除，后台保留记录不做物理删除。
[000005] 4.3 SP-FR-02 展示墙与首页组织（P0）
首页结构自上而下为：置顶轮播位（最多 5 个，由老师或管理员配置）、分类导航、标签筛选条、作品卡片瀑布流、分页加载。
分类固定四类，与论坛板块的技术方向命名保持一致：警务 AI、数据警务、网络安全、前后端开发。分类由后台配置，可增删停用，不在前端写死。
标签为自由标签，由投稿人填写，后台可合并同义标签、屏蔽违规标签。单作品标签上限 5 个。
作品卡片至少展示：封面图、作品名称、来源类型标识、技术栈标签、团队成员（头像与昵称，不显示真实姓名）、校内评分、体验入口。
排序默认按上墙时间倒序。提供"最新""评分优先"两种排序，不提供"最热"排序，避免以流量为导向。
支持按分类、标签、来源类型、是否有在线体验四个维度筛选，筛选条件可组合并写入 URL，便于分享。
移动端小程序与公开 H5 页共用同一套列表接口，分页大小与卡片结构一致。

[000005] 4.5 SP-FR-04 在线体验与外链中转（P0）
作品可配置一个体验地址，支持 H5 链接、可下载的演示包链接、视频演示链接三种形态，形态由作者在投稿时选择。
点击"在线体验"不直接跳转，先进入中转确认页，页内展示：作品名称、目标域名、一句风险提示（"该作品由学员开发，内容未经平台审核，请注意账号与设备安全"）、继续访问与返回两个按钮。
确认后跳转，同时记一次体验记录（uid 或访客标识、作品 id、时间戳、来源页）。中转页记录到达即计一次"体验点击数"，实际跳转计一次"体验完成数"，两个指标分开统计。
地址有效性巡检：系统每日对全部体验地址做一次可达性探测，连续 3 天不可达的作品在详情页展示"体验地址暂时不可用"，并在作者后台提示更新，不自动下架作品。
禁止在平台内直接内嵌渲染第三方页面，不加载第三方脚本，不做 iframe 嵌套，规避脚本注入与数据外泄风险。
[000005] 4.6 SP-FR-05 评论与点赞（P0）
评论采用两级结构：一级评论 + 对一级评论的回复，更深层级折叠为"查看更多回复"。
评论需登录且实名，访客不可评论。评论内容支持纯文本与表情，不支持外链与富文本，降低注入与导流风险。
作者可回复评论，回复带"作者"标识。老师与助教的回复带"教师"或"助教"标识。
点赞为一作品一次，可取消，校内与访客点赞分开计数，页面展示合计值。
评论不做前置审核（与第九章偏离条款一致），但支持助教与老师折叠。被折叠的评论默认隐藏，显示"该评论已被折叠"与展开入口。
同一用户在同一作品下的评论频率限制为每分钟 3 条、每日 30 条，超限提示稍后再试。
评论区提供按"最新""最有帮助"两种排序，"最有帮助"以点赞数为主、作者回复为加权。
[000005] 4.7 SP-FR-06 星级评分与质量参考（P0）
评分为 1 至 5 星整数，一文一用户一评，可修改不可重复提交。修改后以最新一次为准，历史记录保留用于异常检测。
详情页展示的评分仅统计校内实名用户，展示平均值、评分人数与五档分布。访客评分只计入热度，不参与平均分计算，不进入榜单。
评分权限：校内实名用户对任意作品可评分；作者不得给自己的作品评分；同一设备同一账号 24 小时内对同一作品只计一次。
异常检测：同一 IP 段短时间内集中对同一作品给出极端评分、或新注册账号批量评分，标记为可疑并进入后台待核队列，可疑评分不计入平均分直至人工确认。
作者可对明显失实的评分发起一次复核申请，由助教或老师裁定，裁定结果不公开具体评分人信息。
单作品有效评分数少于 5 时，详情页展示"评分样本不足"，不展示平均分，避免小样本误导。
[000005] 4.8 SP-FR-07 版本迭代与变更记录（P1）
一个项目对应一个作品页，作者可持续提交新版本。每个版本记录版本号、变更说明、提交时间、封面与体验地址快照。
详情页默认展示最新版本，提供版本时间线，可回看历史版本的简介与截图，历史版本的体验地址默认失效。
版本更新不重置评分与评论，但在评论区插入一条系统记录："作者于 X 时间发布 V2 版本"，便于读者理解上下文。
版本提交频率限制为每个作品每日 1 次，避免反复刷更新位。
[000005] 4.9 SP-FR-08 搜索与筛选（P1）
支持按作品名称、简介、技术栈标签、作者昵称搜索，标题与标签维度做中文分词，简介维度可按资源降级为前缀匹配。
搜索结果支持按分类、来源类型、评分区间二次筛选。
不提供按浏览量排序的搜索排序选项。

[000005] 4.11 SP-FR-10 置顶与教学范例（P0）
置顶位由老师与管理员配置，最多 5 个，支持设置生效时间与下线时间，到期自动下线。
置顶与"教学范例"是两个独立标记：置顶只影响首页展示位置，教学范例影响标识展示与课例回流资格。老师可将任一作品设为教学范例，数量不限。
教学范例作品在详情页固定展示范例标识，并进入"教学案例"专区列表，供自学平台与老师取用。
[000005] 4.12 SP-FR-11 课例回流授权（P1）
课例回流采用"作者授权 + 老师审批"双条件，不由系统自动流转。
流程：作者在作品管理页发起课例授权申请，勾选授权范围（仅校内教学使用、可用于公开课程、可改编）→ 老师审批 → 通过后广场调用 IF-10 在自学平台生成课程案例草稿，带入作品简介、截图、体验地址与作者署名。
授权为可分次撤回：作者可申请撤回复权，撤回后已生成的课程案例保留但不再更新，且标注"原作者已撤回授权"。
授权记录、审批记录、撤回记录全部入库留痕，作为知识产权争议时的依据。
[000005] 4.13 SP-FR-12 内容治理与巡查（P0）
全量放行机制下，治理依靠三道防线，缺一不可：
机审标记：作品与评论提交时过敏感词与图片审核（IF-06），命中风险词或疑似涉密表述时不在前台拦截，而是打风险标签并推送至巡查队列首位。
日常抽查：助教每日对新增作品按不低于 30% 的比例抽查，重点覆盖标注为警务场景、含真实数据截图、含地图与监控画面的作品。
举报驱动：任何用户与访客可一键举报，举报进入队列并触发 2 小时内响应承诺。
处置动作：折叠评论、下架作品（置为不可见但保留记录）、删除作品（仅管理员，需填写理由并留痕）、对作者发出整改通知。
下架不等于删除：被下架作品在作者后台显示下架原因与整改指引，整改后可申请恢复，由老师复核。
巡查记录包含巡查人、时间、结论、处置动作与理由，不可删除。
[000005] 4.14 SP-FR-13 举报与申诉（P0）
举报理由分类：涉密与敏感信息、违法违规、侵犯知识产权、虚假作品（盗用他人成果）、低质与广告、其他。
举报必填：理由分类、补充说明（涉密类必填）、可选截图。举报人身份对作者不可见。
响应承诺：涉密类举报 2 小时内先行下架待核；其他类 24 小时内给出初步结论。
被处置方可发起一次申诉，由管理员终审。申诉期间处置保持生效。
举报处理结果通知举报人（不透露处置细节中的个人信息），形成闭环。
[000005] 4.15 SP-FR-14 数据看板与埋点（P1）
埋点覆盖：展示墙曝光、卡片点击、详情页停留、体验点击数、体验完成数、评论提交、评分提交、收藏、分享、举报。
后台看板至少包含：作品上墙量与来源分布、体验转化漏斗（曝光 → 详情 → 中转 → 跳转）、评分分布、反馈量趋势、举报与处置时效、分类内容供给均衡度。
看板数据不对外公开，仅老师与管理员可见；助教可见本板块范围。
所有统计指标需注明口径与统计周期，避免同一指标多处口径不一致。

[000006] 第五章 业务流程
[000005] 5.1 SP-BP-01 工坊项目推送上墙流程
工坊项目终期验收通过 → 产生 EV-04 事件 → 工坊侧点击"推送到成果广场" → 广场按 projectId 幂等校验，生成作品草稿并带入项目基础信息 → 通知队长补全展示信息 → 队长提交 → 广场调用 IF-07 复核验收状态 → 校验通过则上墙、写入 EV-05、触发积分分账 → 通知全体成员。
异常分支：IF-07 校验失败则退回草稿并提示原因；队长 7 天未补全则提醒一次，14 天未补全转为"待补全"归档，不占用首页展示位。
[000005] 5.2 SP-BP-02 自主投稿流程
作者进入投稿页 → 选择来源类型 → 填写作品信息与成员权重 → 勾选涉密承诺书 → 提交 → 机审打标签（不拦截） → 立即上墙并写入 EV-05 → 进入当日巡查队列 → 助教抽查 → 无问题则维持展示；有问题按 SP-BP-04 处置。
[000005] 5.3 SP-BP-03 在线体验与反馈流程
访客或学员在详情页点击"在线体验" → 进入中转确认页（记录体验点击数） → 确认跳转（记录体验完成数） → 返回广场 → 可选点赞、评分、评论 → 反馈通知作者 → 作者在后台查看反馈汇总并决定是否提交新版本。
[000005] 5.4 SP-BP-04 巡查与下架处置流程
触发源有三种：机审风险标签、助教日常抽查、用户举报。
任一触发 → 进入处置队列 → 助教初审 → 判定无问题则关闭并记录 → 判定有风险则按等级处置：一般问题折叠或整改通知，涉密与违法问题立即下架并上报老师 → 老师复核并决定是否删除 → 通知作者（含理由与整改指引） → 作者可申诉一次 → 管理员终审 → 全程留痕。
[000005] 5.5 SP-BP-05 置顶与课例回流流程
老师浏览作品 → 设为教学范例并（可选）置顶 → 通知作者 → 作者发起课例授权申请（选择授权范围） → 老师审批 → 通过则调用 IF-10 在自学平台生成课程案例草稿 → 自学平台侧老师补全教学结构后发布 → 作品详情页关联区展示"已被 XX 课程引用"。
[000005] 5.6 SP-BP-06 毕业归档与校友态流程
学生毕业 → 论坛侧账号转为校友态（总纲 3.3） → 广场同步：保留全部作品展示，作者可管理本人作品但不可投稿 → 作品继续作为传承资产保留 → 若作者申请下架，按 SP-FR-01 规则从公开展示移除、后台留档。

[000006] 第九章 内容安全与合规（含 NFR-02 偏离声明）
[000005] 9.1 偏离事项
总纲 NFR-02 规定"全部用户生成内容先过敏感词与图片审核，再按策略决定先发后审或先审后发，警务类、涉密类内容一律先审后发"。
广场平台不完全适用该条：本平台确定采用"全量放行、事后巡查"策略，作品与评论提交后立即公开，不设前置人工审核。偏离范围为 NFR-02 中"警务类、涉密类内容一律先审后发"的强制要求，其余部分（敏感词与图片审核必须执行、审核日志不可删除）继续适用。
偏离理由：广场定位为成果展示窗口，作品上墙具有时效性与传播诉求，前置审核会在学期末集中交付期形成积压，导致作品长期不可见，闭环出口失效。因此以"提交即公开 + 强追溯 + 快响应"替代"先审后发"。
[000005] 9.2 补偿性控制（偏离的生效前提）
以下五项必须全部实现，缺任一项则本偏离条款自动失效，恢复为 NFR-02 原要求：
涉密承诺书：投稿前强制勾选，内容含"本作品不含国家秘密、警务工作秘密、未脱敏的真实警情与人口数据、可识别的监控画面与地理坐标"，勾选人、时间、IP 入库留痕，可追溯到具体责任人。
机审必过：敏感词与图片审核必须执行，命中高风险词的作品打标置顶至巡查队列，并在详情页对校内用户展示"内容待核"提示。
2 小时响应：涉密类举报 2 小时内先行下架待核，超时未处理计入运营考核。
可追溯：所有投稿、编辑、评论、举报、处置行为留痕，日志不可删除，满足 NFR-04 的实名可追溯要求。
校方红线清单：上线前取得校方提供的警务内容红线清单，并据此维护敏感词库。
[000005] 9.3 责任主体
内容安全的最终责任人为平台管理员，日常巡查责任人为助教，涉密判定与终审责任人为指导老师。三者职责不得由同一人兼任。
[000005] 9.4 需确认事项
本偏离条款需提交总纲负责人书面确认后方可生效，确认结果记入附录 D。在确认前，广场按"仅工坊来源免审、非工坊来源人工审核"的过渡策略上线，待确认后切换为全量放行。
